# Daily Skills — 公司每日工作日报

根据用户提供的今日工作内容（口头要点、聊天记录、提交说明、会议结论等），整理成可直接粘贴到企业微信 / 飞书 / 邮件的日报。

## 默认模板

除非用户给出公司固定模板，否则统一使用下列结构与标题（勿改标题用词）：

```markdown
【日报】YYYY-MM-DD（周X）

一、今日完成
1. …
2. …

二、进行中 / 未完成
1. …（当前进度：约 X%；卡点：…）

三、明日计划
1. …
2. …

四、问题与风险
- 无 / 具体问题（影响、是否需升级）

五、需要协助
- 无 / 需要谁、做什么、最晚何时
```

无「进行中」「问题」「协助」时，对应小节写「无」，不要删节。

## 工作流程

1. **收素材**  
   优先用用户本次给出的要点。素材不足时，最多追问 3 个短问题：  
   - 今天做成了哪几件事？  
   - 有没有没做完 / 卡住的？  
   - 明天打算先做哪几件？  
   用户明确说「按这些写」或「随便整理」时，不要再追问。

2. **归类**  
   - 已闭环、可验收 → 今日完成  
   - 开了头未闭环 → 进行中（尽量写进度与卡点）  
   - 明确要明天做 → 明日计划  
   - 阻塞、延期、质量隐患 → 问题与风险  
   - 要别人配合 → 需要协助

3. **成稿**  
   - 中文，书面、简洁，一行一事  
   - 动词开头：完成 / 修复 / 联调 / 评审 / 排查 / 推进  
   - 尽量带对象与结果：模块名、需求名、结论、数据  
   - 不写空话（「忙了一天」「正常推进」单独成条不算）  
   - 不编造用户没说过的进度、结论、承诺  
   - 默认不写工时；用户要求再加

4. **日期**  
   - 用户指定日期 → 用指定日  
   - 否则用当天本地日期，格式 `YYYY-MM-DD（周X）`，周X 用中文

5. **输出**  
   - 默认只输出一篇完整日报正文，可直接复制  
   - 用户要「先提纲」时，先给 3～5 条要点确认，再成稿  
   - 用户要改语气（更短 / 更正式 / 给领导看）时，保持章节结构，只改表述

## 写作约束

- 一条只写一件事；完成项避免「等」「大概」「可能」  
- 进行中必须能看出进度或下一步，禁止只写任务名  
- 问题要写清影响；协助要写清对象与诉求  
- 脱敏：勿写入密码、token、内网未公开地址、完整手机号等  
- 用户贴了公司模板时：**标题与字段顺序以用户模板为准**，本 skill 只负责填内容和润色
