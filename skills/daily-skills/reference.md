# 日报字段与变体说明

## 各节写什么

| 章节 | 应包含 | 避免 |
|------|--------|------|
| 今日完成 | 已交付结果、可验证结论 | 「学习了」「看了代码」且无产出 |
| 进行中 | 任务 + 进度 + 卡点/下一步 | 只有需求名 |
| 明日计划 | 可执行的下一步，按优先级 | 「视情况」「随便看看」 |
| 问题与风险 | 现象、影响、是否已升级 | 情绪宣泄、甩锅表述 |
| 需要协助 | 对象、具体请求、期望时间 | 「大家都支持一下」 |

## 条目句式（推荐）

```text
[动作] + [对象] + [结果/范围]
完成 XXX 模块 YYY 功能开发，并自测通过主流程
修复 XXX 在 ZZZ 场景下的空指针问题，已合入 develop
与 AAA 完成 BBB 接口联调，确认请求/响应字段
```

## 常见变体（用户指定时切换）

### 三段精简版

```markdown
【日报】YYYY-MM-DD

【今日完成】
- …

【明日计划】
- …

【备注】
- 风险 / 协助 / 无
```

### 带项目前缀

每条前加项目名，便于多项目并行：

```text
1. 【WMS】完成入库单筛选修复，并与测试核对
2. 【盘点】准备需求评审材料
```

### 周报扩展（仅当用户说写周报时）

在日报结构上增加：本周目标回顾、跨团队依赖、下周重点；不要把周报默认当成日报。

## 与 Git / 聊天记录配合

用户说「根据今天的提交写日报」时：

1. 查看当日 commits / PR 标题与说明  
2. 按业务语言改写，不要直接粘贴 commit hash 当正文  
3. 合并同需求的多条提交为一条完成项  
4. 纯 chore/格式化提交通常不单独成条，除非用户要求详尽

## 质量自检

输出前快速检查：

- [ ] 日期与星期正确  
- [ ] 五段都在（或已按用户模板）  
- [ ] 没有编造进度与承诺  
- [ ] 没有密钥、密码、敏感内网信息  
- [ ] 可直接复制粘贴
